# Nemotron 3.5 Super VL 120B A12B UD-Q6_K_XL

- Launcher: `variants/AI_Agent_Qubitz_Nemotron-3.5-Super-VL-120B-A12B-UD-Q6_K_XL.py`; requires project-root `qubitz_runtime/`. Select it through `AI Agent Qubitz.py --variant AI_Agent_Qubitz_Nemotron-3.5-Super-VL-120B-A12B-UD-Q6_K_XL.py` or run that variant directly.
- Model: [Unsloth's requested GGUF](https://huggingface.co/unsloth/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-GGUF/tree/main/UD-Q6_K_XL), based on NVIDIA's 120B-total / 12B-active hybrid Mamba-2, attention and MoE model, not a dense 120B model.
- Base: the existing Nemotron-3.5-Lightning-30B-A3B variant has the closest Nemotron-H language architecture; the Ornith 122B adapter supplies only complete-shard acquisition and dual-GPU/RAM fitting.
- Four exact `NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-UD-Q6_K_XL-0000N-of-00004.gguf` files live under `.cache/models/unsloth/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-GGUF/UD-Q6_K_XL/`. Startup selects shard one only after checking all four siblings. Published aggregate size is 120,985,852,968 bytes, about 112.7 GiB; the tiny first shard alone is not the model's memory requirement.
- Tier: `48 GB VRAM+`, selecting `CUDA0,CUDA1` with layer fitting and 1536 MiB headroom on each GPU. The developer host has two RTX 3090 24GB cards and 128GB RAM; other users need sufficient available RAM, not exactly 128GB. Weight overflow stays in CPU-addressable memory; actual fit and speed require live measurement.
- Context default: `262144`; output default: `16384`; automatic-fit minimum: `131072` when feasible. NVIDIA's [configuration](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-BF16/blob/main/config.json) declares `llm_config.max_position_embeddings: 1048576`, so 1M is the native ceiling, not the default preallocation request. Larger `--num-ctx` requests remain subject to memory fitting. No RoPE extension is added.
- Text sampling follows NVIDIA's model card: temperature `1.0`, top-p `0.95`, top-k disabled, min-p disabled, repetition penalty `1.0`, presence penalty `0.0`. The vision-specific temperature is not applied to text requests.
- Isolated upstream [llama.cpp b11788](https://github.com/ggml-org/llama.cpp/releases/tag/b11788), after the [Super VL support commit](https://github.com/ggml-org/llama.cpp/commit/cd0a5b6), avoids silently reusing older shared binaries. Windows CUDA 12.4 uses `.cache/llama.cpp-b11788/`; native WSL fallback has a separate `.cache/llama.cpp-b11788-linux/` build directory and the same pinned source tag. Neither runtime is downloaded or built by model-free checks.
- Attention KV defaults to `q8_0`; recurrent-state precision is not changed. MTP/speculative decoding and the vision projector are not enabled. This is the existing Qubitz text/tool workflow, not an image/video implementation or a measured acceleration claim.
- Metadata provenance: GGUF revision `75a5829055f69a0359085ae6bbd0a81b60bc05c6`; official configuration revision `1f8953f7f0935358e3605150d22bc15df062061c`. These identify the inspected metadata, not a guarantee that future online downloads from `main` are immutable. Model license: OpenMDW-1.1, as stated by NVIDIA, not MIT.
- Verification is model-free. Weight acquisition, real loading, full-context feasibility, inference quality, speed, tool-call parsing and vision remain unverified until separately exercised.
